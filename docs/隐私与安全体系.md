## 二、核心安全保障措施

| 安全措施 | 说明 |
|---------|------|
| 数据加密存储 | 私密数据使用用户专属密钥加密，即使数据库泄露也无法解密 |
| 用户身份验证 | 每次API请求都验证用户身份，返回的数据经过权限过滤 |
| AI数据边界 | AI处理时明确传入"当前用户身份"，只访问该用户有权限的数据 |
| 防绕过设计 | 即使技术高手也无法通过API绕过权限（服务端强制验证） |
| 审计日志 | 记录所有数据访问行为，异常访问会触发警告 |
| 访问频率限制 | 防止恶意批量请求，异常频率会触发验证 |

## 三、AI处理时的数据边界示例

```javascript
// AI生成"妈妈的视角"时，数据查询逻辑伪代码
async function generateMomPerspective(userId, scenario) {
  // 1. 确认当前用户身份
  const currentUser = await verifyUser(userId);
  
  // 2. 查询妈妈画像（只使用妈妈公开或妈妈分享给当前用户的信息）
  const momPublicData = await queryFamilyMember({
    memberId: "mom",
    requesterId: userId,
    permission: "public_or_shared_to_requester"
  });
  
  // 3. 查询当前用户分享给妈妈的信息（用于理解"妈妈眼中的用户"）
  const userSharedToMom = await queryUserSharedData({
    userId: userId,
    sharedTo: "mom"
  });
  
  // 4. 不查询当前用户的私密信息（妈妈不知道）
  // 私密数据 = 不查询
  
  // 5. 生成妈妈的视角
  return aiGenerate(momPublicData, userSharedToMom, scenario);
}

// AI生成"用户的视角"时，可以使用用户私密信息
async function generateUserPerspective(userId, scenario) {
  // 1. 确认当前用户身份
  const currentUser = await verifyUser(userId);
  
  // 2. 查询用户公开信息
  const userPublicData = await queryFamilyMember({
    memberId: userId,
    requesterId: userId,
    permission: "public"
  });
  
  // 3. 可以查询用户的私密信息（因为是用户自己的视角）
  const userPrivateData = await queryPrivateData({
    userId: userId,
    requesterId: userId  // 只能访问自己的私密数据
  });
  
  // 4. 生成用户的视角
  return aiGenerate(userPublicData, userPrivateData, scenario);
}
```

## 四、数据库权限矩阵

| 数据类型 | 用户本人 | 家庭成员 | 其他用户 | AI系统 |
|---------|---------|---------|---------|--------|
| 公开家庭数据 | ✓ 可读写 | ✓ 可读 | ✗ 不可访问 | ✓ 可读（需身份验证） |
| 半公开数据（用户A→妈妈） | ✓ 可读写 | ✓ 妈妈、可读 | ✗ 其他成员、不可访问 | ✓ 可读（仅相关功能） |
| 私密数据（用户A） | ✓ 可读写 | ✗ 不可访问 | ✗ 不可访问 | ✓ 可读（仅用户A视角功能） |

## 八、用户隐私教育

系统会在关键节点教育用户隐私机制：

| 场景 | 提示内容 |
|------|---------|
| 首次使用私密空间 | "这里是你的私密空间，只有你能看到。AI会使用这些信息更好地理解你，但不会影响其他家人的AI版本。" |
| 记录私密信息后 | "已保存为私密。如果你想分享给家人，可以随时修改可见范围。" |
| 角色互换功能使用前 | "AI呈现的'妈妈视角'是基于妈妈知道的信息，不包括你的私密想法。" |
| 设置隐私权限 | "你可以选择公开、半公开或私密。私密数据只有你能看到，公开数据所有家人可见。" |

## 九、技术实现要点

| 实现要点 | 说明 |
|---------|------|
| 数据库设计 | 每条记录包含 `visibility` 字段（public/semi-public/private）和 `visible_to` 字段（用户ID列表） |
| API权限验证 | 所有数据查询API必须传入 `requester_id`，服务端验证权限 |
| AI调用封装 | AI调用时传入 `context_type`（public/semi/private），AI只访问相应层级数据 |
| 加密密钥管理 | 每个用户有专属加密密钥，私密数据使用该密钥加密 |
| 日志审计 | 所有数据访问记录到审计日志，包括访问者、访问时间、访问的数据范围 |
| 定期安全检查 | 定期扫描异常访问模式，如某用户频繁尝试访问他人私密数据 |
